# 示例：技能库重复规则整合

> 示例，非真实执行。本文演示 `plan-driven-development` 台账结构与判断方式，使用合成路径与结果；不得作为项目事实、测试记录或审批依据引用。

## 1. 背景与现状

- 合成问题：三个写作技能各自复制标题层级、表格与图示规则，修改一处需同步三处。
- 现状：规则文本重复，缺少统一静态检查；未确认是否存在已安装副本与生成物。
- 约束：不删除技能能力，不改写已确认技术结论；示例不声称已读取真实仓库。

已确认事实：本示例只提供结构，不提供真实文件行号。待验证假设：重复规则可通过单一权威引用消除。

## 2. 目标与范围

- 目标：重复规则只保留一处权威定义；三个技能改为指针；静态检查能拦截坏格式。
- 非目标：不重写文章正文；不新增内容研究方法；不改变技能触发描述之外的职责。
- 范围：三个写作技能与一个共享规则文件；不覆盖项目专属技能。
- 完成定义：引用无断链、静态检查通过、人工抽查无能力丢失。

## 3. 设计决策

| 决策 | 选择 | 理由 | 被否方案 / 代价 |
|---|---|---|---|
| 规则归属 | 单一权威文件 | 避免多处漂移 | 各技能保留副本：同步成本高 |
| 技能改法 | 保留方法，删除重复清单 | 维持单一职责 | 全量删除：能力丢失 |
| 校验 | 静态结构检查 + 人工抽查 | 结构可自动验证，语义需人工 | 仅人工：易漏 |

## 4. 影响文件

| 文件/模块 | 变更类型 | 影响 | 验证方式 |
|---|---|---|---|
| `path/to/skill-a/SKILL.md` | 修改 | 删除重复规则，加权威指针 | 引用检查 + 人工比对 |
| `path/to/skill-b/SKILL.md` | 修改 | 同上 | 同上 |
| `path/to/skill-c/SKILL.md` | 修改 | 同上 | 同上 |
| `shared/references/example-standard.md` | 新增 | 规则唯一源 | 静态检查 |

接口与数据影响：无运行时接口；技能触发描述不变。兼容影响：旧文档不批量迁移。

## 5. 实施清单

- [ ] 1. 建立权威规则文件，覆盖标题、表格、图示与检查边界 — 完成条件：章节完整，无项目词。
- [ ] 2. 在技能 A 删除重复规则并加指针 — 完成条件：技能仍能独立说明方法与失败模式。
- [ ] 3. 在技能 B、C 做同样修改 — 完成条件：三处指针一致，无第二份清单。
- [ ] 4. 接入静态检查 — 完成条件：好夹具 0 error，坏夹具命中预期编号。
- [ ] 5. 人工抽查技能触发与内容职责 — 完成条件：无能力丢失，无误触发。

## 7. 风险

| 风险 | 影响 | 概率 | 缓解 | 触发信号 |
|---|---|---|---|---|
| 删除清单导致能力丢失 | 技能质量下降 | 中 | 先把方法与失败模式留在技能，再删结构清单 | 抽查发现无法回答原问题 |
| 指针路径在安装后失效 | 技能不可用 | 中 | 安装副本随技能生成；静态检查拦截 | 安装目录引用断链 |
| 规则仍被复制 | 继续漂移 | 低 | 审计重复段落 + 人工比对 | 修改需同步多处 |

## 8. 回滚

- 回滚单位：单个技能提交或整组改动。
- 恢复被删除的技能段落；按原路径回退，不用破坏性 Git 命令。
- 生成物回滚后重新生成，不手工修复。
- 回滚后重新运行结构检查与人工抽查。
