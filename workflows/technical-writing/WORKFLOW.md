# Workflow: technical-writing

## 目的

把技术资料 / 研究 / 排障 / 方案内容，重组成面向读者的技术文章，去 AI 味，并排版成微信 HTML。

## 适用场景

- 公众号技术文章
- 技术博客
- 系列文章（需结构一致性）

## 阶段流水线

```
技术资料
  → 内容整理
  → wechat-tech-article（选题 / 结构 / 草稿）
  → humanizer-zh（按需润色，保持事实与技术限定）
  → producing-tech-blog（排版成微信 HTML）
```

## 每阶段用到的 Skill

| 阶段 | Skill |
|---|---|
| 选题 / 定标题 / 组织结构 / 草稿 | `wechat-tech-article` |
| 去 AI 味 | `humanizer-zh` |
| 排版成微信 HTML | `producing-tech-blog` |

## 产出物

- 内容草稿（见 `templates/technical-article.md`）
- 去 AI 味后的正文
- 微信 HTML（`.md` + 内联 CSS 的 `.html`）

## 检查清单

- [ ] 开头适合读者与文章目的，结构按内容选择
- [ ] 事实 / 分析 / 观点三分离
- [ ] 英文技术词保留原文
- [ ] 润色未新增事实、作者经历或反馈，未改变数字、技术语义和不确定性
- [ ] 排版符合微信规范（内联 CSS，无外部依赖）
- [ ] 系列文章结构一致

## 阶段交接与完成状态

交接时携带输入范围、项目与版本、产物路径或正文、证据引用、验证状态及待确认项。同一版本且相关文件与条件未变化时复用已核验记录，变化时仅重核受影响部分。后续阶段不得默认上游推断已成为事实。

按用户范围执行必要阶段；已有产物满足条件时直接从对应阶段继续。明确区分分析完成、设计完成、执行验证与归档完成；未执行的实验和未完成的客户端预览单独列出。
