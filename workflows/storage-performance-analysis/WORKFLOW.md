# Workflow: storage-performance-analysis

## 目的

从性能现象出发，确认指标、定位调用链与瓶颈，通过源码分析给出优化方案，并验证效果。

## 适用场景

- 延迟异常
- 吞吐不足
- 队列深度异常
- IO 调度 / NUMA / 中断相关性能问题

## 阶段流水线

```
性能现象
  → 指标确认
  → 调用链
  → 瓶颈定位
  → 源码分析
  → 优化方案
  → 性能验证
  → 设计文档
```

## 每阶段用到的 Skill

| 阶段 | Skill |
|---|---|
| 性能现象 → 瓶颈定位 | `storage-debug` |
| 调用链 / 源码分析 | `storage-code-analysis` |
| 优化方案 / 设计文档 | `design-document` |

## 产出物

- 性能分析报告（见 `templates/performance-analysis.md`）
- 优化方案设计
- 验证结果

## 检查清单

- [ ] 指标先确认（延迟 / 吞吐 / 队列深度 / 时延分布），不凭感觉
- [ ] 调用链完整（应用 → 文件系统 → Block Layer → 存储栈 → 驱动/硬件）
- [ ] 瓶颈定位有数据支撑
- [ ] 优化方案有对比与取舍
- [ ] 验证前后指标可对比、可判定
- [ ] 结论带出处，推测明确标注

## 阶段交接与完成状态

交接时携带输入范围、项目与版本、产物路径或正文、证据引用、验证状态及待确认项。同一版本且相关文件与条件未变化时复用已核验记录，变化时仅重核受影响部分。后续阶段不得默认上游推断已成为事实。

按用户范围执行必要阶段；已有产物满足条件时直接从对应阶段继续。明确区分分析完成、设计完成、执行验证与归档完成；未执行的实验和未完成的客户端预览单独列出。
