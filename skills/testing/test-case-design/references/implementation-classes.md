# 实现分类与优先级

## 执行类别

- **自动化**：通过 API、客户端命令和现有验证能力实现，可在测试框架内重复执行。
- **故障注入**：依赖故障注入或可控并发时序实现，需要可控暂停点或故障开关。
- **手工**：当前框架能力不足，需要手工编排。

手工不代表低优先级，也不代表永久无法自动化。写明手工原因及转为自动化所需能力。

## 优先级默认值

采用项目已有优先级规则；缺失时使用：

- **P0**：核心数据安全、保护对象误释放、不可恢复故障等发布阻断场景。
- **P1**：主要功能、关键异常、故障恢复和兼容场景。
- **P2**：次要组合、体验及补充覆盖。

## 实现批次

根据风险、依赖和实现成本单独确定实现批次，不把某一执行类别固定为第一批或第二批。
