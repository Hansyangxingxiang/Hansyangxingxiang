# 按风险选择场景

仅检查适用维度；不适用时说明理由，不扩张产品契约。

### 正常、边界与非法输入

覆盖适用的：

- 正常操作及完整生命周期。
- 最小值、最大值、边界内外、零值和溢出。
- 对齐要求、单位转换、跨对象与跨 shard。
- 配置上限、产品上限和协议上限分别生效及组合生效。
- 非法输入的返回语义和无副作用要求。

### 配置与状态

检查：

- 默认配置、配置组合及实际生效值。
- 动态修改、客户端刷新及旧元数据处理。
- 允许、拒绝、过渡和恢复状态。
- thin/thick、快照、克隆及保护对象等适用限制。

配置显示值不能直接替代运行时能力验证。

### 并发与重试

并发用例必须明确：

- 参与方及各自操作。
- 相同、部分重叠或不重叠的数据范围。
- 暂停位置和状态建立方法。
- 操作交错与完成顺序。
- 解除暂停条件。
- 最终数据、状态及副作用的判定依据。

区分确定时序测试和随机压力测试。没有可控暂停点时，记录所需测试钩子；随机压力只能作为补充，不能声称覆盖了指定时序。

重试场景按需区分：

- 请求未执行。
- 已执行但响应丢失。
- 部分执行。
- 重复提交。
- 旧元数据引发 reopen 或 retry。

按已确认契约判断结果，不臆造幂等或线性化保证。

### 故障与恢复

写明：

- 注入位置、故障类型、持续条件及影响范围。
- 故障是否实际生效及验证方式。
- 请求返回和期间服务行为。
- 故障解除、任务恢复和资源恢复。
- 恢复后的数据一致性、服务状态及遗留任务检查。

### 异步与容量

分别验证：

1. 请求受理或接口完成。
2. 逻辑状态或映射变化。
3. 后台任务完成。
4. 物理空间释放或重新可用。

容量断言必须明确统计对象、单位、副本口径和观测时点。

- 验证卷级分配量时，使用经当前版本确认的卷级统计接口。
- 验证物理回收、池级可用容量或调度时，使用对应指标和接口。
- 不以 volume_allocated 变化替代后台物理回收完成。
- 不以池级容量变化单独证明目标对象释放正确。

使用 `list_volume(..., stat_rep=True)` 前，实读确认参数支持、字段含义、缓存刷新路径及锁竞争行为。缓存周期、StatReplica 和 statLock 行为均需有当前版本证据。

### 性能与稳定性

用例注明：

- 基线版本与环境。
- 负载、数据规模及并发配置。
- 预热、采样窗口和重复次数。
- 吞吐、IOPS、尾延迟、资源占用或回收速率。
- 阈值及来源。

无确认依据的数值标为待评审，不生成实测结果。
