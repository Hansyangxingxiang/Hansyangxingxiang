# Storage Debug — 假设驱动，先分层再下钻

## Overview

排障不是乱试，而是**假设驱动**：先分层定位问题在哪一层，再对每个候选根因写可证伪假设，用工具收集证据，最小复现验证。核心产出是**排障记录单**，每条结论带证据。

## When to Use

- 空间未释放（删除/覆盖后空间没回来）
- 性能异常（延迟、吞吐、IO 卡顿）
- IO 行为不符预期（DISCARD 没下发、写放大、顺序变随机）
- 崩溃、卡死、数据不一致
- 需要从现象反推根因并设计验证实验

## 核心方法

### 1. 分层定位法

按层切割问题域，确定问题在哪一层：

```
应用层      → 应用行为、系统调用（strace）
文件系统层  → ext4/xfs 行为、DISCARD 策略（dmesg、mount 选项）
Block Layer → 请求合并/调度、discard 处理（blktrace、iostat）
存储栈      → RBD/QBD/Store 处理（ceph daemon、日志）
驱动/硬件   → NVMe/SSD 行为（nvme-cli、smartctl、dmesg）
```

每层问：这一层的行为与预期是否一致？不一致 → 问题在这一层或更下层。

### 2. 证据收集工具对照表

| 层 | 工具 | 看什么 |
|---|---|---|
| 应用 | `strace -f -e trace=file,ioctl` | 系统调用序列、参数 |
| 文件系统 | `dmesg`、`mount`、`df`、`stat` | 挂载选项、空间统计、错误 |
| Block Layer | `iostat -x`、`blktrace` | 队列深度、IO 大小、discard 请求 |
| 存储栈 | `ceph daemon <osd> dump_ops_in_flight`、`ceph osd tree`、日志 | 请求处理、空间统计 |
| 驱动/硬件 | `nvme list`、`smartctl -a`、`nvme id-ns` | 命名空间、discard 支持、磨损 |

采集前确认工具开销与权限；`blkdiscard` 等改变数据的操作不作为观测工具。复现实验记录目标、影响范围、已有授权和恢复条件。

### 3. 假设表法

对每个候选根因写假设表：

| 假设 | 预测的可观察结果 | 验证方法 | 结果 |
|---|---|---|---|
| 假设 A：本次操作未产生 DISCARD | 覆盖该操作完整窗口的块层抓取中没有 DISCARD | 核对在线 discard 与周期 fstrim 路径、抓取范围及丢事件情况 | 支持/反驳/证据不足 |
| 假设 B：当前路径拒绝或忽略 discard | 当前版本能力检查或请求跟踪显示不支持或未处理 | 核对能力、请求返回与处理链；空间不降或缺日志不能单独证明不支持 | 支持/反驳/证据不足 |

每个假设必须**可证伪**——能设计实验推翻它。

### 4. 最小复现

- 最小化变量：最小环境、最小操作序列，一次只改一个
- 先复现，再定位；复现不了先缩小范围
- 记录：环境、命令、原始输出

## 排障记录单模板

```
## 现象
- 一句话：<什么操作、什么环境、什么表现、何时开始>

## 分层定位
- 应用层：<证据>
- 文件系统层：<证据>
- Block Layer：<证据>
- 存储栈：<证据>
- 驱动/硬件：<证据>
- 当前定位：<层或尚未定位；依据及缺口>

## 假设表
| 假设 | 预测 | 验证方法 | 结果 |

## 根因
- 状态：<已确认 / 高可信假设 / 未定位>
- 结论或候选解释：<一句话，不超出证据>
- 支持证据与反证：<每步带出处；未排除的替代解释>
- 下一步实验：<最能区分候选解释的实验、预测与判定条件>

## 证据附录
- 命令、日志、源码位置

## 下一步
- 根因确认？→ 交接 design-document 出方案
- 未确认？→ 按需使用 storage-code-analysis 补充源码证据 / 继续缩小范围
```

## Common Mistakes

- **跳过分层直接猜** — 不定位层就下结论，容易修错地方
- **假设不可证伪** — "可能是缓存问题"没有预测，无法验证
- **一次改多个变量** — 无法归因
- **不记录原始输出** — 证据丢失，无法复核
- **把现象当根因** — "空间没释放"是现象，根因在某一层

## 输入、交付与证据复用

- 输入：故障现象、环境版本、日志与可用观测条件。
- 交付与完成条件：排障记录：现象、假设及反证、根因状态、下一步实验。未定位也可交付记录，但不能宣称根因确认。
- 输入不足时先完成有依据的部分，仅询问影响结论或执行的关键缺口。
- 交接证据包含仓库、commit、文件或符号、结论与验证状态。同一版本且相关文件与运行条件未变化时复用已核验记录；版本、文件或关键条件变化时重核相关结论，不重复开展全部研究。
