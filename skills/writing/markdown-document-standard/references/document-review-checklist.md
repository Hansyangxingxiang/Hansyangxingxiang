# 文档质量审查清单

本清单用于人工审查与发布前检查。`scripts/doc_lint.py` 只能覆盖其中可静态判定的部分；不得用脚本结果宣称技术正确性或渲染结果已验证。

## 一、缺陷分级

| 级别 | 含义 | 处理 |
|---|---|---|
| P0 | 技术事实错误、结论无依据、敏感信息、伪造数据、破坏已确认设计 | 必须修复，未修复不得发布 |
| P1 | 结构缺失、关键流程/异常未覆盖、图文矛盾、链接失效、图不可读 | 必须修复或说明 |
| P2 | 表达、排版、术语不一致、冗余、可读性问题 | 按需修复 |

## 二、格式检查（可静态）

- [ ] 只有一个 H1。
- [ ] 标题层级不跳级，编号连续，风格一致。
- [ ] 表格分隔行合法，列数与表头一致，转义正确。
- [ ] 所有围栏闭合，语言标识正确；ASCII 图用 `text`。
- [ ] 相对链接与锚点存在。
- [ ] 无行尾空格，无连续多个空行，代码外无 Tab。
- [ ] ASCII 图未超宽，未用 Tab，未混用框线风格，有图注。
- [ ] 指定文档类型时，元数据必需键齐全，无未说明的占位符。

命令：

```bash
python3 scripts/doc_lint.py --profile new --strict <files>
python3 scripts/doc_lint.py --profile legacy <old-doc.md>
```

## 三、内容检查（人工）

- [ ] 有明确的技术目标与非目标。
- [ ] 关键结论有依据：源码、日志、命令输出或官方文档。
- [ ] 事实、推断、建议、待验证清晰分离。
- [ ] 未编造函数、字段、日志、错误码、行号、实验数据或性能数字。
- [ ] 正常流程、完成条件、异常路径、并发与恢复均已覆盖。
- [ ] 取舍说明了收益、代价、适用边界与不采用其他方案的原因。
- [ ] 无空章节、无机械填充、无重复段落。
- [ ] 关键术语有解释；英文技术词保留原文，术语前后一致。
- [ ] 未把设计文档、论文、未合并 PR 当作当前实现。
- [ ] 未把推测、计划或单条日志写成根因。

## 四、图形检查（人工）

- [ ] ASCII 图方框对齐、边框闭合。
- [ ] 箭头方向正确，无悬空箭头，箭头语义在图注说明。
- [ ] 组件职责清晰，角色与实际系统一致。
- [ ] 控制路径与数据路径未混淆；同步/异步明确。
- [ ] 无必要交叉与过长连线；必要时已拆图。
- [ ] 一图一问题；图注写出问题、条件与图例。
- [ ] 图后正文解释；图文与术语一致。
- [ ] 未画出不存在的直接调用关系。
- [ ] 图是概念示意还是实际实现已说明。

脚本不能验证以上项目；出现“脚本通过但图不可读”时，以人工审查为准。

## 五、文档类型专项

### 架构设计

- [ ] 背景、问题、目标/非目标、约束齐全。
- [ ] 总体架构与控制/数据路径分离。
- [ ] 数据一致性、并发、异常、恢复、兼容与回滚覆盖。
- [ ] 被否方案与选择理由明确。
- [ ] 测试与验收可执行。

### 源码分析

- [ ] 版本/commit 与代码基线明确。
- [ ] 入口、触发条件、调用链、异步边界清楚。
- [ ] 关键数据结构、状态、不变量与完成条件明确。
- [ ] 异常/超时/重试/错误路径覆盖。
- [ ] 结论区分事实、推断、待验证，并给出证据索引。

### RCA

- [ ] 现象、影响、时间线、证据、触发链、根因分层。
- [ ] 根因由证据闭环支撑，不是单条日志。
- [ ] 临时规避与永久修复分开。
- [ ] 验证结果区分已执行、未执行、受阻。
- [ ] 预防措施具体可验证。

### 性能分析

- [ ] 指标定义、单位、数据来源明确。
- [ ] 环境、版本、配置、工作负载与复现条件明确。
- [ ] 瓶颈假设有验证实验，不是仅凭曲线推断。
- [ ] 优化前后对比条件一致。
- [ ] 残留风险与未验证项列出。

### 技术原理

- [ ] 从问题推进到机制与取舍，不做“什么是 X”式科普。
- [ ] 先模型后流程；正常与异常分开。
- [ ] 完成条件、可见性、正确性约束明确。
- [ ] 图不必多，但必须回答问题。
- [ ] 术语与系列锚点一致。

### 实施计划

- [ ] 范围与非目标明确。
- [ ] 任务分解可执行，每项有完成条件。
- [ ] 依赖顺序、影响文件、兼容与回滚明确。
- [ ] 验证计划可执行。
- [ ] Checklist 反映实际进度，不把计划写成已完成。

## 六、审查记录

记录：审查人、日期、文档版本/commit、检查项结果、未运行项、P0/P1/P2 数量、结论。

无法验证的内容（客户端渲染、微信预览、真实集群实验）标为“未运行/受阻”，不得标为通过。静态检查通过只代表格式与结构满足规则，不代表技术结论正确。
