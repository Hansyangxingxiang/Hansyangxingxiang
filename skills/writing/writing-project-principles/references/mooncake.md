# Mooncake 项目配置

> 本文件是 `writing-project-principles` 的项目参考配置，属于**规划约束**，不是未经核实的实现事实。
> 任何架构、行为、参数和性能结论，写作时都必须按 `references/evidence-rules.md` 重新固定版本并核验。

## 一、系列定位

- 系列名：**《Mooncake 技术原理：从 KV Cache 到分布式推理数据层》**
- 目标读者：分布式存储、云原生与 AI Infrastructure 工程师。
- 目标：解释 Mooncake 如何把推理场景的 KV Cache 组织成可共享、可分层、可恢复的分布式数据层，以及它与推理框架的集成边界。
- 非目标：逐函数源码导读、产品功能清单、生产故障排查、部署手册、公众号排版。

## 二、重点范围

- KV Cache 基础与前缀复用条件
- Mooncake Store
- Transfer Engine
- 元数据与数据路径
- 对象放置、副本、生命周期与缓存淘汰
- DRAM/SSD 分层
- 故障处理
- 与推理框架的集成边界

只做当前任务已授权的只读探测，不为补齐配置自动部署、压测或注入故障。缺少环境时继续完成有证据的原理分析，将实验列为验证方案。

若实际具备上述无 GPU 示例环境，可按权限与安装状态评估主机 DRAM Put/Get、跨节点传输、对象生命周期与故障实验的可行性；能力存在仍不等于实验已运行。

无 GPU 示例环境的结果不能据此声称：

- 验证了 GPUDirect 或 GPU 显存直通。
- 验证了真实模型的前缀复用效果。
- 验证了端到端推理收益。
- 所有前缀匹配、调度、传输逻辑都由 Mooncake 自身负责。

额外约束：

- 「Put/Get 成功」不证明数据走了远端 RDMA；需要位置与传输证据（数据落在哪个节点/segment、传输计数器或日志、对照实验）。
- 无法区分路径时，写「未能证明」，不用成功结果反推机制。
- 涉及未实际运行的实验，标为「验证方案」，并写清目的、环境、步骤与预期观察。

## 六、术语锚点

写作时以官方文档和源码为准；下表只固定写法，不预写未经核实的定义。

| 术语 | 统一写法 | 首次出现的中文解释 | 备注 |
|---|---|---|---|
| KV Cache | KV Cache | 注意力机制中的 Key/Value 张量缓存 | 不翻译为「键值缓存」作为正式名 |
| prefix cache / prefix reuse | prefix cache、prefix reuse | 前缀缓存、前缀复用 | 与推理框架的命名对齐 |
| Mooncake Store | Mooncake Store | Mooncake 存储层 | 不简写成 Store 造成歧义 |
| Master | Master（元数据服务） | 元数据服务 | 首次说明角色，之后统一 |
| Client | Client | 客户端 | 区分请求方与存储方角色时显式说明 |
| Transfer Engine | Transfer Engine | 传输引擎 | 首次出现给英文全称与职责 |
| Segment | Segment | 可被远端访问的连续地址空间 | 以官方定义为准 |
| BatchTransfer | BatchTransfer | 批量传输 | 保留原始拼写 |
| replica | replica（副本） | 副本 | 不用「拷贝」混写 |
| eviction | eviction（淘汰） | 缓存淘汰 | 与删除（remove）区分 |
| Pin | Pin | 固定/钉住对象 | 以源码语义为准，不臆造 |
| DRAM tier / SSD tier | DRAM tier、SSD tier | DRAM 层、SSD 层 | 不写成「内存层/磁盘层」混用 |
| RDMA | RDMA | 远程直接内存访问 | 首次解释，之后保留英文 |

新增术语先查官方文档和源码；无法确认时标注「待核验」，不要编造定义。
