# 通用方法：证据分级、交付与复用

本文件是仓库内**唯一手维护**的通用规则源。`scripts/skill_audit.py --write` 会把它逐字节生成到各 Skill 的 `shared-method.md`；生成副本不要手工修改，改这里后重新生成。

Skill 主文件只保留本技能特有的输入、交付与完成条件，通用规则引用本文件。

## 证据分级

- **事实**：当前版本源码 `file:line` 实读、命令输出、日志、官方文档或用户确认的架构。
- **推断**：基于事实的合理推理，必须显式标注。
- **建议**：个人判断、取舍或方案推荐，必须显式标注。
- **待验证**：无法直接验证、需实验 / 源码 / 用户确认才能定的结论。

既有 Skill 使用 `分析` 时按 `推断` 理解，使用 `推测` 时按 `待验证` 理解；仅统一语义，不批量改写既有文本。

## 源码位置规则

- `file:line` 必须来自本轮实读，不信任记忆中的行号。
- 文件路径与符号名作为稳定定位依据，行号作为辅助。
- 无法访问源码时标为未复核，不声称已确认。
- 不编造函数名、参数、返回值、结构体字段、日志串或实验结果。

## 输入不足

- 先完成有依据的部分，仅询问影响结论或执行的关键缺口。
- 缺失项标为"待补"，不用通用经验替代目标系统的实现事实。

## 交付与证据复用

- 交接证据包含：仓库、commit、文件或符号、结论与验证状态。
- 同一版本且相关文件与运行条件未变化时，复用已核验记录并注明来源。
- 版本、文件或关键条件变化时，只重核受影响结论，不重复开展全部研究。
- 未执行的实验、未完成的客户端预览单独列出，不能标为通过。

## 取舍顺序

存储类结论的取舍顺序：**稳定性 > 性能 > 新功能**。任何取舍先论证不破坏数据正确性。
